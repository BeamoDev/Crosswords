# Word Hunt

The current client uses the authored Home and Game screens. Standard has private beginner rounds and shared boards with server-local queues: the first queued player or bot starts a 15-second countdown, later players join that countdown, and everyone still waiting at expiry receives the same server-generated themed puzzle. Players below 10 completed puzzles receive private companion queues; graduates join real players. Classic uses 9x9 with seven short words below ten solves, then 12x12 with 10-12 words. Shape is chosen once for the whole queue, and the authored board/word panels follow the grid layout. Each player finds their own words. Word rows show the headshots of the round members who have found that word. Each player gets a portrait background from a shuffled 30-colour palette at about 80% saturation with a darker stroke, stable across all words in a round and refreshed on the next board. Row dividers stay visible; locally found words are struck through, take their completed line colour as the row background, and move to the top of the list. Each word shows at most three finder portraits; additional finders use the authored Assets.Exceeds clone with TextLabel.Text set to +X (four finders show +1).

Standard uses the authored `Main.Queue`, with `Assets.PlayerTemplate` cards in Queue.Container showing each queued player's headshot, display name and level. Each queue mugshot gets a random background at about 80% saturation and a darker matching stroke, chosen once when its card is created and retained through roster/countdown updates. Queue.Exit leaves the queue and fades back to Home; Subtitle counts down as `Classic Mode (15s)`. At dispatch the view fades to full white over 0.7 seconds, mounts Game, then fades back over 0.8 seconds while panels slide in and controls grow with a small bounce. The existing letter reveal runs alongside it. Guidance binds `Main.Tutorial`. The authored `Home.Pattern`, `Game.Pattern` and `Queue.Pattern` images continuously fade ImageTransparency from 0.98 to 0.92 and back, with four-second sine easing in each direction; missing Pattern images are optional.

Mini, Jumbo and Hardcore start a new random solo board directly from Home, with no queue. Mini unlocks at Level 5 (6x6, five short words), Jumbo at Level 10 (16x16, twenty words), and Hardcore at Level 20 (12x12, twelve longer words in all directions). One incorrect straight selection ends Hardcore; Mini and Jumbo allow mistakes. All use validated words, hints, XP and finder portraits. Standard remains available at every level. Home's Shop, Settings, Leaderboard and Daily buttons open the retained authored modals; Duel opens the challenge lobby. Daily is a login reward, not a puzzle mode.

Standard, Mini, Jumbo, Hardcore and Duel all use the same white entrance and panel reveal. Game.Exit leaves the round directly: controls shrink and panels slide back in reverse order while the screen fades to white, then Home appears as white clears. The game layout restores under white for the next round. Manual pause remains available, and its Leave button uses the same exit transition. Buttons and board input stay locked until each transition finishes; late round updates cannot reopen an exited board.

Classic, Themed, Freeplay, Backwards, Fog, OneLife, Mega and Daily gameplay have been removed. Theme word pools remain shared content. Duel keeps its challenge/countdown/race flow with a dedicated Duel definition. Existing Timed header/panel presentation is preserved; this source does not currently have a Timed gameplay launcher or countdown rules.

The random theme rotation contains 34 packs. Roblox, Brainrot, Obbies, Tycoons, Pet Collecting, Football, Basketball and Racing join the original themes, and Sports has a larger word pool. All eight new packs have enough eligible words for Standard, Mini, Jumbo, Hardcore, Duel and the retained Timed definition. They use the existing random rotation rather than a separate pack selector.

This UI-only game does not spawn avatars: ServerBootstrap sets `Players.CharacterAutoLoads = false` before any startup waits, so no baseplate is needed. Player accounts, profiles, portraits and multiplayer queues still work without a character. ClientBootstrap waits for initial replication, copies the authored Main and GroupIntro from StarterGui only when absent, and keeps both at ResetOnSpawn=false. GroupIntro plays before Main is enabled, using the same interface on every device. Both bootstraps install immediate root anchoring/velocity clearing as a fallback for existing or explicitly spawned characters. Server replication focuses on the fixed CamPart instead of an avatar.

Music uses the existing client Audio system: tracks 72191087451264, 133244468349763, 9045766377 and 136037234851815 play in that order and loop at volume 0.2. Playback starts after GroupIntro and respects the saved Music setting.

The background uses the world sky. At server startup, Operations creates or reuses an invisible, anchored `Workspace.CamPart` at `(-225.271, 136.93, -519.269)` with Orientation `(15.309, 40.884, 0)` degrees. Every client holds that pose at FOV 40, including after respawns or camera replacement. The server publishes its CFrame through a ReplicatedStorage attribute so the view works when the distant part is streamed out. Terrain Clouds cover/density/color and Lighting brightness/ambient colors ease between four daytime settings, three minutes per transition. Time stays between 11:00 and 15:30; the former night cycle is removed. Existing sky assets are preserved.

The client does not assign or clear UI focus. Tutorial steps, queue entry, game starts, pause/resume and keyboard board movement never set GuiService.SelectedObject. Manual navigation remains available.

## Classic board format and admission

Classic uses the saved progression.solves count (all completed boards, including Duel wins; tutorial practice does not count). Below 10 solves, each player gets a private 15-second Standard queue and round with only themselves and simulated companions. Exiting an unfinished board does not advance the admission threshold; existing players with 10 or more solves go directly to the shared queue. There is no new profile field or data reset.

| Classic rounds | Board | Words | Word length | Placement |
| --- | --- | --- | --- | --- |
| Below 10 solves | 9x9 | 7 | 3-6 | east/south/southeast |
| 10+ solves | 12x12 | 10-12 | 3-10 | east/south/southeast/southwest |

PuzzleCatalog.BeginnerThemes contains five curated familiar-word pools (Animals, Yummy Food, Let's Play, At Home, Outside), separate from the 34 full themes. Seeded selection and canonical placement still vary each round. Beginner companions use the existing verified-headshot and adaptive-pacing logic, with no challenger allowed to finish first. Each private pool prepares 2-11 bots, levels 1 through owner level + 2, with disjoint IDs below -2000000000. Ready bots join one at a time with deadline-aware spacing (at least 0.45 seconds), so all eleven can enter the 15-second countdown rather than being limited to a few arrivals. Unavailable headshots never block the round or admit default portraits; a round can start with fewer companions. Private pools are independent of the public 12-slot filler budget, including in full real servers. Their lobby is frozen during play; final portraits stay until Exit, and cancellation/disconnect/generation failure/shutdown disposes private ownership.

Classic below ten saved solves uses 9x9, seven familiar 3-6-letter words and E/S/SE directions. At ten solves it switches to 12x12 with 10-12 themed words and E/S/SE/SW directions. The beginner board has 43.75% fewer cells; difficulty reduction is approximate. BuildClassicDefinition applies this policy to private queues and Queue.Solo/replays from authoritative saved solves. Placement retries preserve dimensions; skill averaging is not used.

QueueUpdated is sent per recipient. Beginners see only their own private roster/count/deadline (empty before joining), while graduates see the public queue. A server publication revision increases across both streams, so graduation cannot make the client reject a lower private/public queue revision. Existing authored Main.Queue, transitions, cards and round membership rules remain in use.

Returning players who finished or skipped onboarding go straight to Home; new players and unfinished newer profiles still receive the tutorial. Saved history and other progress remain intact.

After the win message, the tutorial panel collapses and the spotlight fades out, then the normal reversed Game panels and white fade return to Home. Three seconds after typing finishes, the frame shrinks to zero and closes. Play opens the two-word practice board immediately, with its normal entrance animation. Separate queue, theme, board, word-list, XP and reward explanations are removed. Exit/pause and unrelated gameplay stay locked during practice; Skip remains connected throughout.

## Progression reset

The profile namespace remains `WordHuntQueueData_v1`, key `player_<UserId>`, now schema version 19. The compact profile stores progression.level/xp/solves/wordsFound/duel, hints, dailyReward and prepared dailyPuzzle progress, plus small fields required by the active shop/settings/tutorial/account rewards and safe purchases/saves. Existing levels, XP progress, hints, pieces, Duel results and once-only flags migrate without a reset. Timed rewards and irrelevant statistics/archives are removed. [PLAYER_DATA.md](PLAYER_DATA.md) lists the exact saved defaults, mirrors and snapshot contract. Global Words Found and 1v1 Wins rankings use `WordHuntQueueWordsFound_v1` and `WordHuntQueueDuelWins_v1`; the former Level index is left untouched. Existing players enter the new indexes as their profiles load; no historical profile export or reset is performed.

`progression.wordsFound` saves the lifetime number of accepted words and mirrors to `Player.Data.Progression.WordsFound`. Classic/private beginner, solo and Duel finds count once; duplicates, hints alone, bots and tutorial practice do not. Leaving an unfinished puzzle retains its accepted words. Existing profiles start missing word counters at zero, without a data reset.

`Level` is the only leaderstat. Validated words award 20 XP per letter, a completed board awards 120 more XP, and advancing from Level L requires 500 + 100 * (L - 1) XP: 500, 600, 700, and so on. Both authored LevelBars show the server snapshot. Reaching even levels grants 2 hints and odd levels grants 1 hint (starting at Level 2). Game.LevelBar previews `LEVEL X REWARD` and `+1 Hint` or `+2 Hints`; crossing several levels grants all their rewards once. Existing levels do not receive retroactive rewards. Hint products, piece purchases, daily/group/gift rewards and server receipt compatibility remain available. Supported paid receipts are acknowledged only after their grants and receipt IDs save successfully.

`ProgressionConfig.Experience.Levels[1..500]` is the shared backend dictionary for player levels. Each immutable entry contains `level`, cumulative `totalXp`, `xpToNextLevel`, destination `rewardHints` and cumulative `totalRewardHints`. Existing XP/reward readers use these entries; the same formula continues beyond Level 500 to preserve progression. This is not a numbered puzzle campaign or a level cap, and it does not change the datastore or XP curve.
